# Побочные эффекты жизни — заметки для Claude Code

Браузерный симулятор жизни. Статический сайт без сборщика: `index.html` подключает классические скрипты по порядку, общее состояние лежит в глобальном `s`. Текущая сборка — 275.

## Как устроен код

- Функции расширяются цепочками обёрток: `const base={fn}; fn=function(){base.fn(); ...}`. Номер в имени файла (`finance43.js`, `habits78.js`) — версия, в которой модуль появился. Порядок `<script>` в `index.html` важен: обёртка видит только то, что загружено раньше неё.
- Ключевые точки: `advanceMonth` / `rollYear` (clock.js, game.js), `queueOnce` / `resolvePending` / `show` / `choose` / `log`, `remember` / `rel`, `save()` (обёрнут больше 30 раз, побочных эффектов в нём быть не должно).
- `save()` с 264 отложенный (save264.js): запись идёт раз в 0.4 с. Если код сразу после сохранения читает хранилище (`localStorage`, `readLife`) или меняет `s`, сначала `flushSave264()` — для уже известных мест это сделано.
- Страны: 25. Первые 14 (`nl rs ru us br jp fr es de uk ca kr cn mx`) есть во всех таблицах, 11 поздних (`it au tr za th no in id eg ma pl`) — не во всех. Новая страновая таблица должна покрывать все 25 или иметь явный запасной вариант.
- Офлайн-режим: каждый новый файл добавлять в `offline-assets.json` (одна строка, без пробелов) и поднимать имя кэша в `offline-worker.js`.
- Очередь окон: `s.pending` + обёртка `resolvePending` по `q.type`. Поле `q.id` в событии очередь (`pendingValid05`) проверяет как живого человека и иначе выбрасывает событие — для питомцев и прочего берите своё поле (`petId`, `personId`).
- С 269 `show()` в events.js больше не вырезает числа из подсказок: «настроение +5» видно. Старые подсказки, написанные словами, остаются как есть.
- Имена и клички не склоняются: в текстах только именительный падеж («Вы и Нина…», «Разговор · Нина», не «с Ниной»). Где важно, чей дом, склоняется роль: `roleGenitive268(p)` → «Живёте у мамы — Мина Павлович». «Вы» в повествовании, «ты» только в «ёлочках»; ё всегда, кроме хранимых значений («Ребенок», «Учеба», «Тетя» — их сравнивают со старыми сохранениями); на экране их показывает с ё display269.js (только текст, не атрибуты), новые такие слова добавлять в `yoDisplay269`. Перед сборкой — `python3 tools/text_audit.py`.
- Лента (feed267.js): рутина идёт не в ленту, а в «Будни» раз в три месяца — новую рутинную запись добавьте в `routine267`. После `log()` не полагайтесь на `s.log[0]`, если запись может оказаться рутиной.
- Театр и лента с 272.2 (feed2722.js): детская студия ставит сказки из каталога детских книг (роли с полом — `stageRoles2722`, педагог выбирает через `autoRole2722`), постановка полгода, роль предлагают один раз — в месяц читки; принятая студией пьеса игрока встаёт в `queued2722`. «Своя жизнь», «новости» и «Знакомое лицо» близких — в «Будни». - Модели, усердие и проверки (решения владелицы 28.11, вместо ультракода): ведущий — Опус, high; исполнитель мелких сборок, текстов, данных, корней — Сонет, high; исполнитель сборок, где трогаются сохранения, деньги или время, — Опус, high, и одна проверка Опус xhigh до выкладки; мелкие сборки — без отдельной проверки, только тесты; разовые простые задачи — Сонет, medium. Модель и усердие задаются при запуске каждого агента. Раз в 4–5 сборок и перед каждой большой (277, профессии) — общая сверка параллельными проверяющими: сохранения и открытие игры (старые сохранения, обновление страницы, наследник); деньги и время (месяц, год, неделя, NaN); экран телефона и тексты; стыки между сборками; несколько длинных жизней до 80 лет. Найденное — одной точечной сборкой. Первая сверка — после 276, 279.1.4, 271.1, 274.x, перед 277.
- Ритм сборок с 272: одна тема на сборку, новые идеи по ходу — в следующую. Полный круг (реализация → независимая рецензия → исправления) — только для того, что может сломать сохранения, деньги или ход времени; тексты, списки и мелкие правки — один проход и тесты. Готовую часть выпускать отдельной точечной сборкой (NNN.1), не дожидаясь соседних.
- Новый код — отдельными файлами в стиле обёрток (`fixesNNN.js`, `pets-deathNNN.js`), подключать в `index.html` перед `bootstrap61.js`. Старые файлы трогать только точечно для настоящих багов и помечать комментарием `// NNN: ...`. Многие файлы — одна длинная строка: внутри неё только `/* NNN: ... */`, иначе `//` закомментирует остаток строки.
- При правке файла поднимать его `?v=` в `index.html` до номера сборки.
- Каждую сборку сопровождать `CHANGES-NNN.txt`: что исправлено, что сознательно не тронуто.
- Тексты игры — на русском, живым языком, без «игровой модели» и пересказа правил (см. раздел «Текст» в docs/ROADMAP.md).
- Формулы баланса проверять прогоном, а не на глаз.

## Проверка

```
python3 -m http.server 8765          # из папки с игрой
python3 tools/verify257.py           # точечные проверки сборки 257
python3 tools/run_lives.py out.jsonl 8 2 100 0.25 7   # N жизней, параллельно, до возраста, доля действий, сид
node tools/calibrate_death.js out.jsonl 6 100 random 7 off   # здоровье по годам, без сервера
node tools/verify.js                                          # точечные проверки 259+, без сервера
node tools/business_bench.js 16                               # своё дело: убытки, закрытия, доход владельца (BASE=1 — старая модель)
node tools/save_bench.js 40 3                                 # сохранение, клик и месяц на персонаже 40 лет
for f in tools/verify270_*.js tools/verify271_*.js tools/verify272_*.js; do node $f || echo "FAIL $f"; done   # части сборок 270–271, без сервера; BASE=1 — без файла части
```

`tools/calibrate_death.js` работает на Playwright, который уже стоит для Node, и раздаёт игру с диска сам, без `http.server`. На каждый год пишет здоровье, сглаженное здоровье и источники его изменений («файл:функция», отдельно потери и прибавки). POLICY `random` — случайный игрок, `care` — то же плюс отдых, «Движение» и врач, `smoker` / `drinker` — с 18 лет сильная привычка, `creative` — карьера иллюстратора (доход, часы, уровень, репутация в снимке). DEATH `off` — смерть только в 100 (снять траектории), `new` — как в игре, `old` — как до 258. Для каждой новой жизни он заново читает файлы с диска: не правьте файлы игры и `index.html`, пока идёт прогон. В Node-Playwright `pg.evaluate("()=>{...}")` строкой функцию не вызывает — передавайте настоящую функцию.

`tools/harness.js` внедряется в страницу: двигает время, отвечает на события, кликает случайные действия, ловит ошибки и NaN. Нужен Playwright (`pip install playwright && playwright install chromium`). Больше 2 жизней параллельно — браузер может падать по памяти; это ограничение прогонщика, а не баг игры.

Полное ТЗ — `docs/ROADMAP.md`. Делаем слоями, каждый слой — отдельная рабочая сборка.

1. **Баги** — сделано в 257, смертность — в 258, перекалибрована в 259 под новое здоровье (`CHANGES-258.txt`, `CHANGES-259.txt`).
